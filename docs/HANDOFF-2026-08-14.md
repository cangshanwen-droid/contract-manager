## 3. 数据模型与业务规则（核心）

### 3.1 云端 gipfel.db
- **users**：`username/password(PBKDF2 sha256)/role(admin/operator/rep)/org_id/company_ids 关联 user_companies/stock_adjustable(1可修改代表/0不可修改主席审计)`
- **user_companies**（user_id, company_id）——**rep 隔离链核心**！`company.region`（公司名如"A区"）→ `regions.name` 匹配 → region_id；`regions.org_id` 常为 NULL（勿依赖）
- **contracts**：状态机 `draft/active/executing/completed/terminated/rejected`；**创建即 active**（无审批流，用户拍板）；`approval_status` 字段遗留（none）
- **contract_items**：`shares/price`（股数/股价，替代旧预期收益率字段）；8 类合同类型（1基建/2开采/3采购/4劳动力/5投资/6拨款/7销售/8减碳）
- **region_accounts**：区域资金账户（A/B/C区主账户）
- **announcements**（公告，region_id NULL=全局）/ **notifications**（站内通知，按 user_id——"告诉本账号"）
- **audit_logs**（审计，username 列无 user_id）

### 3.2 云端 stocks.db
- **users**：`username/role/adjustable(1可修改/0锁定)/balance(可用资金)`——**用户级账户**（一人一个股票账户，余额=users.balance）
- **portfolios**（user_id, symbol, shares, avg_cost）/ **orders**（幂等 idempotency_key 唯一索引）/ **adjust_logs**
- **登录同步**：股票 `/auth/login` 时若 gipfel 有该用户（PBKDF2 校验）→ 自动建/同步 stocks users（含 adjustable）

### 3.3 权限模型（实测证据链）
| 操作 | admin | operator | rep |
|------|-------|----------|-----|
| 买卖股票 | ✅ | ✅ | ✅（`_require_trader`） |
| 调整可用资金（他人） | ✅ | ✅ | ❌ 403 |
| 调 operator/admin 资金 | ❌ 400「操作端/管理端固定100万」 | ❌ | — |
| 调 adjustable=0（主席审计） | ❌ 400「100万锁定」 | ❌ | — |
| 建号/删号/重置密码/用户列表 | ✅ | ❌（get_admin_user） | ❌ |
| 合同创建/驳回 | ✅ | ✅（公司隔离） | ❌ 403 |
| 看用户列表 | ✅ | ❌ | ❌ |

## 4. 桌面端架构（contract-manager）

**Electron**（electron-builder NSIS，`asar:false` 防 OOM；artifactName 纯 ASCII）

```
src/
 ├── main/                # 主进程
 │   ├── index.ts         # 注册所有 IPC handler
 │   ├── ipc/*.handler.ts # auth/contract/account/notification/system...
 │   ├── database/        # 本地 SQLite (contract-manager.db) + migrations.ts (v1-v26)
 │   └── session.ts       # 权限解析（user_roles 主路径 + role 内置 fallback 双保险）
 ├── renderer/src/
 │   ├── pages/           # 页面（见下）
 │   ├── api/cloudApi.ts  # ★ 核心：ROUTE_MAP（60 通道 REST 映射）+ cloudInvoke/invoke
 │   ├── context/AuthContext.tsx
 │   └── styles/design-tokens.ts  # 设计令牌（见 §6）
 └── shared/
     ├── constants.ts     # IPC_CHANNELS（100 通道）
     ├── permissions.ts   # 权限点
     ├── cloud-config.ts  # ★ 云端地址单点（CLOUD_HOST='106.54.26.86'）
     └── types.ts
```

**关键机制**：
- **云端模式恒开启**（`isCloudMode()` 恒 true，用户拍板）——ROUTE_MAP 有映射→云端 REST；无映射→显式抛错（绝不静默降级本地，防数据分叉）；`LOCAL_ONLY_CHANNELS`（文件/备份/凭证/股票直连）
- **cloudInvoke**：GET 无 body；POST/PUT 用条目 `body:` 构造器（否则取最后对象参数）；**散参通道必须配 body 构造器**（曾踩坑：reset-password 缺 body→422）
- **登录**：LoginPage 用 `window.api.invoke(AUTH_LOGIN)`（本地 bcrypt）→ cloudLogin 拿云端 JWT（3s 超时）→ localStorage `gipfel_auth_token`
- **响应结构兼容**：云端返回**纯数组** vs 前端期望 `{success,...}`——解析处必须兼容两种（`Array.isArray(r) ? r : r?.xxx`），已在用户列表/仪表盘行情/健康检查多处修复
- **设计-tokens**：`#061A33/#0F2748 深海军蓝 + #D4AF37 金`；禁 emoji/渐变/霓虹/大圆角/彩色方块/紫色

**页面**：DashboardPage（rep 专属视图+区域卡片+行情）、ContractListPage（8类模板+驳回）、AccountPage（区域账户）、UserManagementPage（建号+股票账户类型）、StockMarketPage（原生工作台）、AnnouncementPage、SettingsPage、InfraCalculator、LandAreaReport、AccountMonitorPage、GlobalSearch

**验证纪律（必须遵守）**：
1. 改代码后 `grep` 编译产物验证（防"改了没生效"）

3. 部署后实测线上行为（200/400/403 状态码），不只看构建通过
4. 测试账号用完即清理（云端 sqlite 直连物理删，API DELETE 软删不可靠）
5. 中文用户名 URL 必须 `urllib.parse.quote`
6. 资金/编号并发 → 条件 UPDATE + rowcount / 幂等唯一索引；`commit_with_retry` 禁 rollback 重试
