# Gipfel 全软件体验与视觉优化计划

更新日期：2026-08-14  
目标：在不破坏权限、业务数据和桌面端稳定性的前提下，将系统统一为高可信、克制、专业的机构金融工作台。

## 1. 体验目标

- 信息密度高但不拥挤：关键数据先于装饰，常用操作保持一屏可达。
- 角色一致但权限明确：管理端和操作员共享同一套交易体验；管理端增加治理能力；代表端严格只读。
- 视觉统一：深海军蓝、暖金、紧凑直角、小尺度描边；不使用渐变、霓虹、发光、浮夸大圆角和低质动效。
- 金融数据规范：金额统一 `¥1,234.56`，数字等宽，涨红跌绿，时间、百分比、空值和精度统一。
- 状态可信：加载、空态、失败、无权限、离线、提交中、成功和危险操作均有清晰反馈。

## 2. 全局 P0 基础治理

1. 修复源码与注释中的历史编码污染，统一 UTF-8、中文术语和角色名称。
2. 建立全局 Design Tokens：颜色、字号、间距、描边、层级、阴影、动效时长、图表色板只保留单一来源。
3. 统一应用壳层：侧栏、顶栏、页面标题、面包屑、全局搜索、通知、网络状态和底部状态栏。
4. 建立统一页面骨架：标题区、关键指标区、工具栏、主体、空态/错误态、分页和危险操作确认。
5. 建立权限矩阵自动测试，确保代表端不出现任何交易与管理入口。

## 3. 模块优化路线

| 优先级 | 模块 | 核心改造 | 验收重点 |
|---|---|---|---|
| P0 | 登录 | 无文案品牌仪表、克制呼吸动效、安全登录区、键盘与错误反馈 | 首屏高级感、无廉价动画、低性能设备稳定 |
| P0 | 股票交易 | 行情磁带、专业 K 线、盘口、订单票、资产与持仓统一工作台 | 蜡烛实体/影线/坐标/成交量/十字光标规范；买卖后即时刷新 |
| P0 | 权限与账户 | 管理端/操作员同构交易功能，管理端追加资金与市场治理，代表端只读 | 前端门控与后端鉴权双保险 |
| P1 | 仪表盘 | 从卡片墙改为决策摘要：异常、趋势、待办、关键资产 | 首屏回答“发生了什么、需要做什么” |
| P1 | 合同 | 高效筛选、状态流、批量操作、详情侧栏、金额与风险摘要 | 大数据表可扫读，编辑/删除风险明确 |
| P1 | 区域与基建 | 指标与列表联动、排序反馈、字典筛选、编辑前后差异 | 数据密度、单位和空值一致 |
| P1 | 资金与账户监控 | 余额、流水、异常、冻结与调账形成审计链 | 金额精度、危险操作、可追溯性 |
| P1 | 用户与公司 | 角色/权限可视化、状态管理、批量处理、关联关系 | 防误操作、搜索和筛选效率 |
| P2 | 模拟计算 | 输入分组、即时校验、结果解释、方案对比与导出 | 结果可理解而非只给数字 |
| P2 | 公告与设置 | 编辑预览、受众范围、发布状态；设置分组和即时反馈 | 表单一致性、保存状态可靠 |
| P2 | 全局搜索与通知 | 命令式检索、最近项、键盘导航、通知分级与已读 | 快捷操作、无死链、权限过滤 |

## 4. 股票工作台专项标准

### 4.1 布局

- 左：可搜索行情与自选股；中：K 线主视图；右：交易票据与五档盘口；下：持仓、订单和成交。
- 宽屏保持三栏，窄屏按“行情 → 图表 → 交易 → 资产”顺序降级，不隐藏关键状态。
- 不复制线上站点的长卡片墙和视口外登录问题，只保持功能语义一致。

### 4.2 K 线

- 中国市场配色：涨红、跌绿、平盘中性；影线与实体同色，极小实体仍可辨认。
- 价格轴位于右侧，时间轴位于底部；刻度数量随宽度调整，避免标签重叠。
- 价格范围加入合理上下留白；最新价使用细虚线和价格标记，不遮挡蜡烛。
- 成交量独立子区，同步涨跌色；高低点只标注关键极值。
- 十字光标显示时间、开高低收和成交量；鼠标离开后回到最新一根摘要。
- 首次加载、无数据、数据不足和请求失败分别呈现，不制造伪造行情。

### 4.3 角色与功能

- 管理端：完整交易、持仓、成交、资金调度、市场状态与治理入口。
- 操作员：完整交易、持仓、成交和所属资金账户操作，与管理端使用同一套核心组件。
- 代表端：行情、K 线、盘口和本人持仓只读；不渲染下单按钮、数量/价格输入或调资入口。
- 所有下单和调资请求携带 `idempotency_key`；中文用户名必须编码；提交期间禁用重复操作。

## 5. 动效与图标

- 动效只服务于层级、状态和空间关系；优先 `transform` 与 `opacity`，避免布局抖动。
- 登录品牌图标保留低频、低振幅的呼吸感；正文和交易数据不持续漂浮。
- 尊重 `prefers-reduced-motion`；关键功能不依赖动画才能理解。
- 图标统一使用同一线性家族，不使用 emoji；只有无歧义的常用动作可省略文字。

## 6. 执行阶段

### 阶段 A：稳定基础（1 个迭代）

- 编码、Design Tokens、壳层、权限矩阵、金额/日期格式化、状态组件和基础可访问性。
- 完成股票工作台、登录页和核心桌面分辨率验收。

### 阶段 B：高频业务（2 个迭代）

- 仪表盘、合同、区域、资金、账户监控、用户和公司。
- 每个模块按“审计 → 原型 → 实现 → 角色测试 → 视觉回归”闭环。

### 阶段 C：工具与细节（1 个迭代）

- 模拟计算、基建字典、公告、设置、全局搜索、通知和键盘操作。
- 补齐空态、错误态、加载骨架、批量操作和导出体验。

### 阶段 D：交付治理（持续）

- 建立视觉回归截图、组件使用规范、DESIGN.md、发布清单和故障回滚流程。
- 每次版本执行 TypeScript、单测、构建、安装包和真实角色实机验收。

## 7. 质量门槛

- `npx tsc --noEmit` 零错误；`npx vitest run` 全通过；生产构建成功。
- 1366×768 与 1920×1080 无横向溢出、遮挡、截断或不可达操作。
- 最小正文 11px；关键正文至少 12px；交互目标建议不小于 32px。
- 键盘可完成登录、导航、搜索、表单提交和弹窗关闭；焦点清晰。
- 断网、慢网、接口错误和空数据均有稳定反馈，不出现白屏或无限加载。
- 管理端、操作员、代表端分别完成权限与业务回归；代表端买卖入口为零。

## 8. Skill 选型原则

- 当前主组合：Impeccable（视觉审计）、UI Skills（工程规范）、Taste（审美方向）、UI/UX Pro Max（交互与可访问性）、Motion（动效）、Better Icons（图标）。
- 仅在出现明确缺口时引入 GitHub Skill；检查 Stars、最近维护、许可证、依赖与脚本内容后再安装。
- 禁止仅因热度叠加功能重合的 Skill，避免规则冲突和不可追踪的生成风格。
