# Gipfel 功能与数据联通审计

审计日期：2026-08-14  
范围：桌面 Electron 客户端、Gipfel 业务 API、股票 API，以及管理端、操作员端、代表端三种角色。

## 结论

股票功能保持在 Gipfel 桌面软件内原生呈现，不使用 iframe，也不要求用户进入独立股票网站。业务 API 与股票 API 是同一桌面界面背后的两个服务：前者是账号、角色、公司与业务数据事实源，后者是行情、股票账户、持仓与订单事实源。

本轮发现并修复了代表端 API 越权、操作员账户目录不可用、K 线最新价不同步、盘口语义误导、服务重启 token 失效、演示账号密码漂移，以及业务资金幂等并发异常。

## 数据边界

| 数据 | 事实源 | 联通方式 |
|---|---|---|
| 用户名、密码、角色、公司归属 | Gipfel 业务 API / `gipfel.db` | 股票登录实时转发业务 API 验证并同步角色与归属 |
| 行情、K 线、成交价位分布 | 股票 API / `stocks.db` | 桌面原生页面直连同域股票路由 |
| 股票余额、持仓、成交订单 | 股票 API / `stocks.db` | Bearer token 绑定本人账户；管理端可代管 |
| 区域基建资金、合同、公告 | Gipfel 业务 API / `gipfel.db` | 桌面 IPC → 云端 REST |

股票余额采用“每用户一个独立股票账户”。合同与区域资金也采用手工入账，不因合同审批或股票成交自动改变区域基建账户。账号和归属统一，但两类资金不做隐式混用。

## 已修复问题

### P0：代表端可绕过前端直接下单

- 原因：桌面端隐藏了交易入口，但股票 API `_require_trader` 仍允许 `rep`。
- 修复：后端仅允许 `admin/operator`；代表端直接调用 `/orders` 返回 403。
- 防回归：股票测试加入 API 角色门控断言。

### P0：资金桥并发幂等冲突进入失效事务

- 原因：通用 `commit_with_retry` 对唯一键冲突也重复 `commit`，未回滚的 SQLAlchemy 会话进入 `PendingRollback`。
- 修复：仅对 SQLite `database is locked` 做提交重试；唯一键冲突回到路由层回滚并读取首次结果。
- 验证：5 个并发同 key 请求只处理一次，业务测试 13/13 通过。

### 高：操作员“资金调度”入口无法加载用户

- 原因：桌面端调用业务 API 管理员用户列表，操作员被 403。
- 修复：股票 API 新增 `/managed-stock-accounts`；管理端和操作员共享，代表端 403；锁定账户在界面禁选。

### 高：服务重启后股票 token 失效

- 原因：股票 token 为进程内存态，服务重启清空；桌面业务会话仍存在。
- 修复：持仓、下单和账户目录遇到 401 时，桌面端使用安全凭据自动续签并重试一次。

### 高：K 线收盘价与行情现价不一致

- 原因：K 线只聚合历史成交，行情表可独立更新最新价。
- 修复：按 UTC 当日新增或更新实时柱，收盘价与行情事实源一致，不伪造成交量。
- 线上证据：JGONG K 线由 2 根增至 3 根，最新 close 与 market current_price 一致。

### 中：把历史成交分布标成五档实时盘口

- 原因：系统采用立即成交，没有常驻委托簿；买卖历史可能穿价。
- 修复：API 返回 `mode=trade-distribution`，桌面明确显示“成交价位分布 / 历史成交聚合，非实时挂单”。

### 中：演示账号密码与交接文档不一致

- 修复：恢复 `代表演示`、`审计演示` 的文档密码，并同时验证业务与股票登录 200。

### 中：合同资金旧测试与现产品规则冲突

- 原因：合同创建已改为直接生效、资金手工入账，但旧测试仍期待审批自动扣款。
- 修复：回归测试改为确认合同流程不会隐式改变区域资金。

## 自动化与构建证据

- 股票 API：unittest 5/5 通过；Python 3.8 语法编译通过。
- 业务 API：pytest 13/13 通过，包含资金原子更新和并发幂等。
- 线上：`gipfel-api`、`stock-api` 均为 active；行情 6 只；三角色权限矩阵符合预期。

## 后续非阻断治理项

1. 股票 token 后续可迁移为签名 JWT，避免多实例与重启丢失会话；当前桌面自动续签已消除主要用户影响。
2. 自签名 IP 证书应迁移到正式域名与受信任证书。
3. CORS 通配、旧 `X-Admin-Key` 管理路由、Pydantic V2 和 `datetime.utcnow()` 弃用警告应分期治理。
4. 如需真正五档盘口，必须引入挂单状态、撮合与撤单模型；在此之前不得把历史成交数据标成实时委托。
